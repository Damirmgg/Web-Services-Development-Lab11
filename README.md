# Task Tracker — лабораторная работа модуля 11

Веб-приложение на Go для управления личными задачами: добавление, просмотр, переключение статуса, удаление и статистика. Данные хранятся в `[]Task` в памяти: обновление страницы сохраняет список, перезапуск сервера очищает его. Начальный список пустой.

## Запуск

Нужны Go 1.20+ и Visual Studio 2022/2026 с рабочей нагрузкой «Разработка классических приложений на C++» для проекта Makefile, как в модулях 09–10. Само приложение написано на Go, сторонних библиотек нет.

1. Распакуйте архив и откройте **TaskTracker.sln**.
2. Выберите **Debug | x64**, нажмите **Ctrl+F5**.
3. Оставьте окно сервера открытым и перейдите в браузере на **http://localhost:8080**.
4. Остановка сервера — **Ctrl+C** в его окне.

Альтернатива: выполните `go run .` в папке с `go.mod` и откройте тот же адрес. После установки Go перезапустите Visual Studio, чтобы она увидела команду `go`.

Обе работы модуля используют порт 8080. Перед запуском другой работы остановите текущую. Если порт занят, сервер сообщит об этом в консоли.

Шаблоны и CSS встроены через `go:embed`. После их изменения пересоберите проект. Swagger и база данных не используются: взаимодействие идёт через HTML-формы.

## Маршруты

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/` | Список задач, форма и статистика |
| POST | `/tasks` | Добавить задачу; поле `title` |
| POST | `/tasks/complete` | Переключить статус; поле `id` |
| POST | `/tasks/delete` | Удалить задачу; поле `id` |
| GET | `/about` | Информация о приложении |

Успешные POST-запросы возвращают перенаправление `303` на `/`, поэтому обновление страницы не повторяет действие. Неправильный метод возвращает `405`, пустое название и некорректный ID — `400`, отсутствующая задача или страница — `404`. Пробелы по краям названия удаляются. ID возрастают и не переиспользуются после удаления.

## Файлы

- `main.go` — запуск HTTP-сервера, маршруты, подключение встроенных файлов.
- `task.go` — структуры Task и PageData, срез, поиск, операции и статистика. Mutex защищает данные при одновременных запросах.
- `handlers.go` — обработка запросов и форм, проверка ID, HTML-ответы и перенаправления.
- `templates/index.html` — главная страница; `templates/about.html` — страница о проекте.
- `static/style.css` — оформление для компьютера и телефона.
- `go.mod` — описание модуля; `.sln` и `.vcxproj` — сборка Go из Visual Studio.

## Что можно показать

1. Добавьте «Изучить net/http» и «Создать HTML-шаблон»: всего 2, выполнено 0, не выполнено 2.
2. Выполните первую: показатели станут 2 / 1 / 1. Нажмите «Вернуть в работу»: 2 / 0 / 2.
3. Удалите первую задачу и создайте новую: оставшиеся ID — 2 и 3, они не совпадают.
4. Обновите страницу: задачи сохранятся. Откройте «О проекте» и вернитесь.
5. Попробуйте название из нескольких пробелов: сервер покажет ошибку, задача не добавится.
6. Откройте `/tasks` в адресной строке: это GET, поэтому ответ будет `405`.

Проверить неправильный и отсутствующий ID можно в PowerShell при работающем сервере:

```powershell
curl.exe -i -d "id=abc" http://localhost:8080/tasks/complete
curl.exe -i -d "id=99999" http://localhost:8080/tasks/delete
```

Первый запрос возвращает `400`, второй — `404`. HTML из названий экранируется пакетом `html/template` и отображается как текст.
